# 一鉴到底平台产品架构全案规范

## Why
豆包对话文档（0602.txt）定义了「一鉴到底·EIHM-P2P-CS + ASS 一体化AI执行操作系统」的完整产品愿景，包含七层架构、三大护城河、老骇心法设计原则等核心战略。当前代码库已有部分能力落地（16个单能力页面、Agent执行中心、统一检测引擎），但与文档愿景存在显著差距，需要系统性对齐和规划。

## What Changes
本规范为**战略级产品架构规划**，涵盖以下变更域：
- **ASS安全内核**：从当前四模块检测升级为四层全链路巡检（输入→静态→动态→输出）
- **EIHM-P2P-CS算力网络**：新增端侧闲时异构微算力P2P协同调度层
- **前端TF推理引擎**：新增浏览器端GPU推理分布式引擎
- **1000+场景原子技能库**：从当前16个单能力扩展到技能插件生态体系
- **老骇心法UI/UX**：全面贯彻0阅读、0决策、强筛选、出事兜底原则
- **轻量在线IDE**：新增Monaco编辑器+安全运行一体化IDE
- **多端插件生态**：VS Code插件 + 浏览器插件
- **商业化体系**：免费版→个人会员(399元/年)→企业版(9999元/年)三级定价

## ADDED Requirements

### Requirement: 七层架构分层实现
系统 SHALL 按照文档第三章定义的七层分层架构进行渐进式实现：

```
第7层：用户应用层 → 主网页版 / 轻量在线IDE / 多端插件 / API接入端 / 客户端
第6层：智能编排与需求拆解层 → 意图识别 / 任务原子化 / 代码非代码分流 / 依赖排序
第5层：ASS全链路安全网关层 → 输入层巡检 / 静态层巡检 / 动态层巡检 / 输出层巡检
第4层：成本路由与调度层 → 成本路由算法 / 安全等级路由 / 地域路由 / 任务分片
第3层：EIHM-P2P-CS算力网络层 → 前端TF推理节点 / 桌面客户端节点 / 自营企业节点
第2层：统一执行引擎层 → 代码沙箱 / Wasm容器 / 技能插件 / 前端TF推理 / 浏览器自动化
第1层：白盒审计与数据合规层 → 全链路不可篡改日志 / 区块链存证 / 操作回放 / 数据不出域
```

#### Scenario: 用户提交文本检测请求的全链路流转
- **WHEN** 用户在主网页输入框提交"帮我检测这段文案"
- **THEN** 请求依次经过：应用层接收 → 编排层拆解为原子任务 → ASS输入层巡检（Prompt注入/敏感词）→ ASS静态层巡检（恶意代码扫描）→ 成本路由选择最优节点 → 统一执行引擎调用对应技能 → ASS动态层巡检（运行时监控）→ ASS输出层巡检（脱敏/签名）→ 白盒审计层记录日志 → 返回结果给用户

### Requirement: ASS四层安全巡检机制
系统 SHALL 实现文档第四章定义的ASS（Agent Security System）全链路安全内核：

#### 4.1 输入层巡检
- 拦截率 ≥ 99.9%，误判率 ≤ 0.1%，单次 ≤ 10ms，支持1000QPS
- 巡检对象：用户Prompt、指令、上传文件、API入参
- 巡检内容：Prompt注入攻击、恶意指令、敏感词、越权请求、脏数据注入
- 处置逻辑：高危拦截/中危脱敏放行/低危静默记录
- **注意**：处置提示语需官方化（见 agent-execution-center-refactor 规范）

#### 4.2 静态层巡检
- 检测覆盖率 ≥ 99.99%，漏洞检出率 ≥ 99.9%
- 巡检对象：AI生成代码、用户上传代码、社区技能脚本、依赖包
- 巡检内容：SQL注入/XSS/CSRF/路径遍历/命令注入、恶意依赖、后门代码、病毒木马
- 技术实现：Semgrep AST分析 + Trivy依赖扫描 + 自研恶意代码特征库

#### 4.3 动态层巡检
- 异常行为识别率 ≥ 99%，拦截延迟 ≤ 10ms，性能损耗 ≤ 5%
- 巡检对象：运行中进程、系统调用、文件读写、网络请求、资源占用
- 技术实现：eBPF系统调用捕获 + Falco运行时规则引擎 + Cgroups资源限制

#### 4.4 输出层巡检
- 敏感数据识别率 ≥ 99.9%，违规内容检测率 ≥ 99.9%
- 巡检对象：返回文本、文件、图片、视频、报表、审计日志
- 巡检内容：敏感数据泄露、违规内容、恶意输出、数据篡改

### Requirement: 老骇心法UI/UX设计原则
所有前端页面 SHALL 严格遵循文档第八章的「老骇心法」五原则：

1. **0阅读**：页面上无多余文字，无教程、说明、帮助文档
2. **0决策**：用户不需做任何选择，所有决策由系统自动完成
3. **强筛选**：自动过滤免费用户，高级功能仅付费用户可用
4. **出事兜底**：平台承担安全责任，显示赔付承诺
5. **老骇风格**：所有文案用大白话和数字（**已通过 agent-execution-center-refactor 规范完成官方化改造**）

## MODIFIED Requirements

### Requirement: Agent执行中心升级为智能编排层入口
`/agent` 页面 SHALL 从当前的「多维协同检测聊天界面」升级为文档第六层「智能编排与需求拆解层」的前端入口：
- 保留现有的四模块协同检测能力（安全审计/真实性核验/数据存证/智能裁决）
- 新增「意图识别」：自动判断用户输入属于哪个技能类别
- 新增「任务原子化」：将复杂需求拆解为可并行执行的原子任务
- 新增「代码/非代码分流」：代码类任务走沙箱执行器，非代码类走技能插件
- 新增「依赖排序」：自动处理多步骤任务的执行顺序

### Requirement: 单能力页面统一化
现有16个单能力页面 SHALL 统一遵循老骇心法设计原则：
- 每个页面只有3个元素：标题 + 输入区 + 执行按钮
- 结果页第一行永远显示「✅ 检测任务已完成」
- 用数字和大白话展示结果，不用技术术语
- 所有次要信息折叠在「详细分析」区域
- 只有一个主要行动按钮（下载报告/重新检测）

### Requirement: 技能插件框架
现有各单能力的后端实现 SHALL 重构为统一的技能插件接口：
- 统一JSON格式输入输出
- 自动集成ASS四层巡检
- 支持热插拔（新技能上线无需重启）
- 执行时间限制 ≤ 10秒，内存限制 ≤ 512MB
