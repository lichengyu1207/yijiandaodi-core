# Agent 执行中心重构规范

## Why

当前 `AIChatCenter.tsx`（/agent 路由，约1956行）存在以下问题：

1. **话术过于个人化**：使用"四官联动"、"老骇风格"等非正式用语，不符合平台产品化定位
2. **架构与产品愿景脱节**：豆包对话文档定义了「一鉴到底·AI执行操作系统」的七层架构（ASS安全内核→智能编排→成本路由→算力网络→统一执行引擎→白盒审计），但当前页面仅呈现四个角色的简单聊天界面，未体现系统级能力
3. **功能堆砌缺乏层次**：欢迎页、执行进度、多Agent协同、工作流编排入口、快速任务等混在一起，缺少清晰的信息架构
4. **角色命名需官方化**：当前"审计官/验证官/存证官/裁决官"偏拟人化，应向专业术语对齐

## What Changes

* 重构 `AIChatCenter.tsx` 为 **Agent 执行中心（Agent Execution Center）**

* 文案全面官方化：去除个人化表达，采用专业产品话术

* 页面结构按「输入→编排→执行→审计」四阶段重新组织

* 角色名称从拟人化官职改为功能模块命名（保留中文但去人格化）

* 新增「执行概览仪表盘」区域，展示系统运行状态

* **不修改**：前端首页信息流（Home/index.tsx 及其子组件）、AgentConfig 配置后台、API 层

## ADDED Requirements

### Requirement: Agent 执行中心页面重构

系统 SHALL 提供统一的 AI 任务执行入口（/agent），支持用户提交内容并获得多维度的安全检测与分析报告。

#### 页面布局架构（三栏式）

```
┌──────────────────────────────────────────────────────┐
│  [左侧边栏]     │        [中央主区域]                │
│                 │                                    │
│  ┌───────────┐  │  ┌──────────────────────────────┐  │
│  │ + 新建任务 │  │  │  执行概览仪表盘（可选收起）    │  │
│  ├───────────┤  │  │  · 系统状态 / 今日任务数       │  │
│  │ 会话历史   │  │  · 各模块健康度 / 平均响应时间   │  │
│  │ · 任务A    │  │  └──────────────────────────────┘  │
│  │ · 任务B    │  │                                    │
```

#### Scenario: 用户提交文本检测任务

* **WHEN** 用户在 /agent 页面选择场景为"文本"，输入检测内容并点击执行

* **THEN** 系统依次调用安全审计→真实性核验→数据存证→智能裁决四个模块，展示实时进度条和各模块结果卡片，最终输出综合报告

#### Scenario: 用户查看执行结果

* **WHEN** 四个模块全部执行完毕

* **THEN** 展示综合评级横幅（安全通过/存在风险/高风险警告）、各模块详细分析、改进建议列表、导出报告按钮

### Requirement: 文案官方化标准

所有用户可见文案 SHALL 遵循以下原则：

1. **无第一人称**：不出现"我"、"老骇"、"帮你"等个人化代词
2. **无口语化表达**：不出现"别瞎搞"、"翻车"、"白嫖"等网络用语
3. **无拟人化角色名**：使用功能模块名称而非官职名称
4. **数据驱动**：用数字和等级代替主观判断词
5. **操作导向**：按钮和提示语以动作+对象格式呈现

| 区域     | 当前文案                    | 官方化后                  |
| ------ | ----------------------- | --------------------- |

| 欢迎语    | 我是审计官，请问有什么可以帮您？        | 安全审计模块已就绪，请输入待检测内容    |
| 成功提示   | ✅ 老骇已经帮你搞定了             | ✅ 检测任务已完成             |
| 风险提示   | ⚠️ 老骇提醒你一下              | ⚠️ 安全风险提醒             |
| 拦截提示   | 🚫 老骇拦你一下！              | 🚫 操作已拦截              |
| 免费额度提示 | 白嫖X次够了                  | 免费额度已用完               |
| 兜底承诺   | 出事我赔，放心用                | 平台安全保障，经检测的任务均受安全策略覆盖 |

### Requirement: 角色模块重命名与定位

四个检测模块 SHALL 从拟人化官职名称调整为功能性模块名称：

| 编码       | 当前名称 | 官方名称  | 图标          | 主色      | 核心能力                   |
| -------- | ---- | ----- | ----------- | ------- | ---------------------- |
| auditor  | 审计官  | 安全审计  | ShieldEye   | #DC2626 | 内容风险扫描 / 敏感信息识别 / 合规检查 |
| verifier | 验证官  | 真实性核验 | CheckCircle | #2563EB | 来源追溯 / 交叉比对 / 置信度评估    |
| archiver | 存证官  | 数据存证  | Lock        | #16A34A | 数字指纹 / 时间戳锚定 / 完整性校验   |
| judge    | 裁决官  | 智能裁决  | Gavel       | #EA580C | 规则匹配 / 风险评估 / 决策输出     |

**注意**：后端 `agent_code` 字段值（auditor/verifier/archiver/judge）保持不变，仅修改前端显示名称。

## 技术约束

1. **不改 API 层**：`agentApi.ts` 的接口调用方式不变，仅修改前端展示层
2. **不改路由**：`/agent` 路由保持映射到 `AIChatCenter` 组件
3. **不改后端模型**：`agent_code`、数据库字段不变
4. **不改首页**：`Home/index.tsx` 及其子组件的信息流内容不动
5. **向后兼容**：`AGENT_ROLES` 数组的 `code` 字段保持原值，确保 API 调用参数正确
