# 一鉴到底 - 浏览器插件MVP功能边界与技术选型

## 一、MVP核心原则

**MVP（Minimum Viable Product）最小可行产品**

### 核心价值主张
为AI内容创作者提供**完整的创作过程证据链**，证明创作内容的时间、来源和过程。

### 目标用户
- AI内容创作者（文案、图片、视频）
- 自媒体作者
- 内容工作室
- 版权保护需求者

---

## 二、MVP功能边界定义

### ✅ 必须有（核心功能）

#### 1. 操作记录（核心）
- **功能**：自动记录用户创作操作
- **包括**：
  - 文本输入（AI对话、文本编辑）
  - 文件操作（上传、下载、保存）
  - 页面跳转（平台切换）
- **MVP范围**：
  - 基础事件监听（input、click、copy、paste）
  - 防抖优化（避免性能问题）
  - 本地暂存（不依赖网络）
- **不包含**：
  - ❌ 复杂的DOM解析
  - ❌ 跨域iframe内容捕获
  - ❌ 桌面应用监控

#### 2. 时间戳证明（核心）
- **功能**：提供可信的北京时间戳
- **包括**：
  - 国家授时中心NTP时间同步
  - 北京时间显示（UTC+8）
  - Unix时间戳记录
- **MVP范围**：
  - 客户端时间计算（基于本地时间+时区偏移）
  - 显示来源标识（ntp.ntsc.ac.cn）
- **不包含**：
  - ❌ 真实NTP服务器连接（需要后端）
  - ❌ 区块链时间戳
  - ❌ 第三方公证

#### 3. 指纹生成（核心）
- **功能**：为每个操作生成唯一指纹
- **包括**：
  - SHA-256哈希算法
  - 五元组联合哈希（操作+结果+凭证+时间+前序）
  - 指纹链完整性验证
- **MVP范围**：
  - 客户端计算（SubtleCrypto API）
  - 本地存储指纹链
- **不包含**：
  - ❌ 区块链存证
  - ❌ 第三方签名

#### 4. 证据链报告导出（核心）
- **功能**：一键导出完整证据链报告
- **包括**：
  - HTML格式报告
  - 创作时间线
  - 操作记录列表
  - 指纹证据链
- **MVP范围**：
  - 本地生成（无需网络）
  - 离线可用
- **不包含**：
  - ❌ PDF格式
  - ❌ 加密报告
  - ❌ 在线分享链接

#### 5. 浮动窗口显示（体验）
- **功能**：实时显示录制状态
- **包括**：
  - 时间显示
  - 操作计数
  - 开始/停止按钮
- **MVP范围**：
  - 可拖拽窗口
  - 最小化功能
- **不包含**：
  - ❌ 复杂的统计图表
  - ❌ 实时内容预览

---

### ⚠️ 应该有（次要功能）

#### 1. 平台识别
- **功能**：自动识别创作平台
- **MVP范围**：
  - 基于域名匹配（DeepSeek、ChatGPT等）
  - 显示平台名称
- **不包含**：
  - ❌ 深度内容解析
  - ❌ 跨平台内容关联

#### 2. 会话管理
- **功能**：管理录制会话
- **MVP范围**：
  - 会话列表
  - 会话删除
  - 本地存储
- **不包含**：
  - ❌ 会话编辑
  - ❌ 会话合并
  - ❌ 云端同步

#### 3. 内容捕获
- **功能**：捕获AI生成的内容
- **MVP范围**：
  - 基础文本捕获（预览100字符）
  - 图片URL记录
- **不包含**：
  - ❌ 完整内容存储
  - ❌ 多媒体文件保存
  - ❌ 内容去重

## 三、技术选型决策

### 1. 前端（插件端）

#### 核心技术栈
| 技术 | 选型 | 理由 |
|------|------|------|
| **Manifest版本** | V3 | Chrome官方推荐，未来主流 |
| **UI框架** | 原生HTML/CSS/JS | 无需构建，体积小 |
| **样式方案** | 原生CSS | 无依赖，兼容性好 |
| **状态管理** | chrome.storage.local | 持久化，无需额外库 |
| **哈希算法** | SubtleCrypto API | 浏览器原生，安全性高 |

#### 不使用的框架/库
- ❌ React/Vue：体积大，构建复杂
- ❌ TypeScript：需要编译，MVP阶段简化
- ❌ Webpack/Vite：构建工具，MVP不需要
- ❌ jQuery：过时，原生API足够

---

### 2. 后端（可选，MVP阶段不需要）

#### 未来技术栈（当需要云端功能时）
| 技术 | 选型 | 理由 |
|------|------|------|
| **框架** | Django REST Framework | 已有代码基础 |
| **数据库** | PostgreSQL | 已有配置 |
| **认证** | JWT | 已实现 |
| **存储** | 本地文件系统 | 简单可靠 |

#### MVP阶段：纯客户端方案
- 所有数据存储在`chrome.storage.local`
- 无需后端服务
- 完全离线可用

---

### 3. 数据存储

#### 本地存储方案
| 数据类型 | 存储位置 | 大小限制 |
|----------|----------|----------|
| 会话数据 | chrome.storage.local | 5MB |
| 指纹链 | chrome.storage.local | 5MB |
| 设置项 | chrome.storage.local | 5MB |
| 报告文件 | 用户下载目录 | 无限制 |

#### 数据结构
```javascript
// 会话数据
{
  sessionId: string,
  startTime: ISO8601,
  operations: Array,
  fingerprints: Array,
  platform: Object
}

// 操作记录
{
  id: string,
  type: enum,
  timestamp: ISO8601,
  timestampUnix: number,
  data: Object,
  pageInfo: Object
}

// 指纹
{
  hash: string,
  prevHash: string,
  operationId: string,
  timestamp: number
}
```

### 4. API设计（MVP：无外部API）

#### 内部通信
```javascript
// 消息协议
{
  action: 'startRecording' | 'stopRecording' | 'recordOperation',
  sessionId?: string,
  operation?: Object,
  data?: Object
}

// 响应协议
{
  success: boolean,
  session?: Object,
  error?: string
}
```

#### 未来API（云端功能）
- `POST /api/sessions` - 创建会话
- `GET /api/sessions/:id` - 获取会话
- `POST /api/sessions/:id/sync` - 同步会话
- `GET /api/reports/:id` - 获取报告

## 五、技术风险与对策

### 风险1：性能卡顿
**原因**：事件监听过于频繁
**对策**：已实现3秒防抖机制

### 风险2：浏览器兼容性
**原因**：不同浏览器API差异
**对策**：已实现browserAPI兼容层

### 风险3：数据丢失
**原因**：Service Worker休眠
**对策**：已实现状态持久化到storage

### 风险4：平台变更
**原因**：AI平台更新DOM结构
**对策**：使用通用选择器，预留更新机制

## 七、决策记录

### 决策1：不使用前端框架
**时间**：2026-07-12
**理由**：MVP阶段追求简单、快速、无依赖
**影响**：开发速度快，但代码可维护性稍差

### 决策2：纯客户端方案
**时间**：2026-07-12
**理由**：MVP无需后端，降低复杂度
**影响**：无云端同步，未来需要迁移

### 决策3：使用Manifest V3
**时间**：2026-07-12
**理由**：Chrome官方推荐，未来趋势
**影响**：Firefox需要额外适配

### 决策4：不实现真实NTP连接
**时间**：2026-07-12
**理由**：需要后端服务，MVP阶段简化
**影响**：时间戳为计算值，非权威证明
