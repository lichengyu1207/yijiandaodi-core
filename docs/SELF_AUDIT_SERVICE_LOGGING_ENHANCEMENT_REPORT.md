- ✅ 方法入口和出口日志（带时间戳）

- ✅ 准确率计算过程（当前准确率、基线准确率）
- ✅ 偏离率计算公式（显示完整计算过程）
- ✅ 阈值对比日志（阈值值、对比结果）
- ✅ 异常创建日志（漂移记录ID、严重程度）
- ✅ 性能监控日志（执行耗时）

## 🔍 日志使用场景

### 场景1：排查准确率漂移误报

**问题**：系统报告准确率漂移，但实际业务正常。

**排查步骤**：
1. 查看日志中的偏离率计算过程：
   ```
   [Self-Audit] 偏离率计算: |0.9333 - 0.9500| / 0.9500 = 0.0175
   ```
2. 检查基线准确率是否合理：
   ```
   [Self-Audit] 基线准确率: 0.9500 (ID: 5, 更新时间: 2026-08-10 08:30:00)
   ```
3. 查看样本数是否足够：
   ```
   [Self-Audit] 统计结果: 总数=150, 安全=140, 危险=10
   ```
4. 根据实际情况调整基线或阈值

### 场景2：排查响应时间异常

**问题**：P99响应时间异常告警。

**排查步骤**：
1. 查看响应时间分布：
   ```
   [Self-Audit] 响应时间统计: 最小=150.00ms, 平均=850.50ms, P99=1950.00ms, 最大=2200.00ms, 样本数=120
   ```
2. 确认样本数是否足够（样本太少可能不准确）：
   ```
   [Self-Audit] 查询完成，找到 120 条包含响应时间的记录
   ```
3. 检查是否有极端值拉高P99：
   ```
   [Self-Audit] 最大=2200.00ms  # 远高于P99的1950ms，可能有个别慢请求
   ```
4. 根据实际情况调整阈值或优化慢接口

### 场景3：排查检查失败原因

**问题**：某个检查项失败，但日志不够详细。

**排查步骤**：
1. 查看异常类型和详细信息：
   ```
   [Self-Audit] 准确率漂移检测失败: BehaviorBaseline.DoesNotExist: BehaviorBaseline matching query does not exist.
   ```
2. 根据日志建议创建缺失的基线：
   ```
   [Self-Audit] 请创建 metric_name='accuracy' 的 BehaviorBaseline 记录
   ```
3. 查看堆栈信息（如果开启了 DEBUG 日志）：
   ```
   [Self-Audit] 异常详情: ...
   ```

### 场景4：性能分析

**问题**：自监控检查执行缓慢。

**排查步骤**：
1. 查看总耗时：
   ```
   [Self-Audit] 总耗时: 125.45ms
   ```
2. 查看各个检查项的耗时（从分隔线到完成的时间差）：
   - 准确率检测: ~45ms
   - 响应时间检测: ~38ms
   - 误报率检测: ~20ms
   - 权限审计: ~15ms
   - 规则时效性: ~7ms
3. 找出最慢的检查项，针对性优化

## 📊 日志级别说明

| 级别 | 用途 | 示例 |
|------|------|------|
| **INFO** | 方法入口、重要结果、性能指标 | `开始检测准确率漂移`、`准确率: 0.95` |
| **DEBUG** | 详细步骤、查询条件、中间结果 | `查询时间范围: ...`、`统计结果: ...` |
| **WARNING** | 异常情况、阈值超限、数据缺失 | `检测到准确率漂移`、`未找到基线` |
| **ERROR** | 检查失败、异常捕获 | `检测失败: ...`、异常堆栈 |

## ✅ 实施效果

### 优势

1. **可追溯性强**：每个关键步骤都有日志，问题可快速定位
2. **调试友好**：详细的计算过程和中间结果，方便验证逻辑
3. **性能监控**：自动记录执行耗时，及时发现性能瓶颈
4. **异常诊断**：详细的异常信息和堆栈，快速定位问题根源

### 注意事项

1. **磁盘空间**：日志量增加，建议配置日志轮转
2. **性能影响**：DEBUG 级别日志有一定性能开销，生产环境建议使用 INFO 级别
3. **敏感信息**：日志中包含业务数据，注意权限控制
